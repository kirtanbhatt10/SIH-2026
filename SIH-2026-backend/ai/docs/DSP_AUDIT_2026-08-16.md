## 2. Actual DSP Architecture

### Constants (single source: `ai/dsp/__init__.py`)

| Constant | Value |
|----------|-------|
| `SAMPLE_RATE` | 48000 Hz |
| `CHUNK_SIZE` / `HOP_LENGTH` | 2048 samples (~42.7 ms) |
| `N_FFT` | 2048 |
| Detection band | 18000–21000 Hz |
| Filter band | 17500–21500 Hz |

### Per-chunk processing order (`DSPPipeline.process()`)

Unlike a linear STFT-first pipeline, **each stage runs its own Hann-windowed rFFT** on the preprocessed chunk:

```
RAW CHUNK (2048 samples, mono float)
  │
  ├─► AudioPreprocessor.process()          → bandpass float32
  │
  ├─► FeatureExtractor.extract()           → 32 features (internal FFT)
  ├─► SpectrogramGenerator.add_chunk_dict()→ 64-bin dB frame + peak_snr_db
  ├─► FrequencyAnalyzer.analyze_and_accumulate() → modulation + suspicion (internal FFT)
  └─► StreamingSegmenter.push()            → onset/offset event (band energy FFT)
```

After all chunks: `DSPPipeline.to_threat_event()` aggregates analyzer verdict, pattern votes, segmentation duration, and peak SNR.

### Stage reference table

| Stage | File | Class/Function | Input | Output | Key parameters |
|-------|------|----------------|-------|--------|----------------|
| Capture | `scripts/pipeline_common.py` | `capture_microphone()` | device_id, duration | float32 mono array | 48 kHz, sounddevice |

## 5. Frequency Detection Logic

**Method:** Hann-windowed `np.fft.rfft`, n=2048, per preprocessed chunk.

**Peak finding** (`FrequencyAnalyzer._detect_peaks`):

1. Reject if max/mean < 3.5 in ultrasonic band
2. `scipy.signal.find_peaks`: height ≥ 15% max, prominence ≥ 8% max, distance ≥ 3 bins (~70 Hz)
3. Return up to 10 peaks sorted by magnitude

**Per-frame modulation** (`_classify_modulation`):

- **FSK:** ≥2 peaks, spacing 400–3500 Hz, second peak ≥20% of first, flatness < 0.4
- **OOK:** 1 peak + envelope ON/OFF metrics (depth, transitions, duty cycle, CV)
- **Chirp:** broad flat spectrum, ≥3 peaks, spread > 1000 Hz
- **Tone:** 1 dominant peak, high tonal ratio
- **None:** no significant peaks

**Multi-frame carriers** (`get_accumulated_verdict`):

- Cluster peak frequencies within **100 Hz**
- Keep clusters appearing in **≥50%** of chunks → `consistent_carriers`

## 6. BFSK Detection Logic

### Expected frequency pair

- **Backend simulator / PC1:** 18500 Hz ↔ 20500 Hz (`FREQ_0`, `FREQ_1`)
- **DSP synthetic generator default:** 19000 ↔ 20500 (configurable)
- **Detection:** any two consistent carriers in 18–21 kHz band — not hardcoded to 18500/20500

### Single frame vs multi-frame

```
Frame duration  = 2048 / 48000 = 42.7 ms
Bit duration    = 50 ms (project default)
Symbols/frame   ≈ 0.85 → usually ONE carrier visible
```

→ Single-frame `analyze()` typically returns **`tone`**, not **`fsk`**.

→ Multi-frame `to_threat_event()`:
  - Clusters carriers across chunks
  - If `len(carriers) ≥ 2` and vote was `tone` → **override to `pattern: "fsk"`**

### Both frequencies required?

- **Per frame:** No — one carrier sufficient for `tone`
- **ThreatEvent `pattern: fsk`:** Yes — needs ≥2 consistent carriers OR occasional dual-peak frame
- **ThreatEvent `detected: true`:** Can occur with **one** consistent carrier (`pattern: tone`) if suspicion thresholds met

### SNR

`peak_snr_db = peak_magnitude_db - mean(magnitudes_db)` in spectrogram frame (64-bin interpolated band). ThreatEvent `snr` = **max across all chunks** — not rigorous SNR vs noise floor.

## 7. Feature Extraction

32 fixed-order features in `FeatureExtractor.FEATURE_NAMES`:

- Energy (4): ultrasonic_energy, total_energy, energy_ratio, energy_db
- Spectral shape (6): centroid, bandwidth, flatness, rolloff, skewness, kurtosis
- Peaks (6): peak_frequency, peak_magnitude, prominence, num_peaks, spacing mean/std
- Tonal (4): tonal_prominence, harmonic_ratio, crest_factor, zero_crossing_rate
- Temporal (6): rms, envelope_std, onset_strength, temporal_flatness, duty_cycle, bit_rate_estimate
- Statistical (6): mean/std/max/min magnitude, range, CV

**Not used for ThreatEvent fields directly** — supplied for future ML (AI 2). Threat scoring uses `FrequencyAnalyzer` heuristics.

---

## 8. Confidence Calculation

**ThreatEvent `confidence`** (`to_threat_event()`):

1. Count per-frame `modulation_type` votes (excluding `none` unless all are none)
2. `vote_share = votes[winning_pattern] / total_votes`
3. If ≥2 consistent carriers and winner was `tone` → force `pattern=fsk`, boost confidence
4. Blend: `max(vote_share * 0.5 + analyzer.last_result.confidence * 0.5, 0)`

**Meaning:** How sure the **modulation classifier** is of its label (uncalibrated).

**Not the same as suspicion_score.**

---

## 9. Suspicion Score Calculation

**Per-frame** (`FrequencyAnalyzer._compute_suspicion_score`):

```
score = 0
+ min(0.3, energy_ratio * 3)           if energy_ratio > 0.01
+ mod_weight[type] * mod_confidence    fsk=0.4, ook=0.35, chirp=0.3, tone=0.2
+ peak structure bonus (up to 0.2)
+ regular spacing bonus (up to 0.1)
cap at 1.0; if type=none cap at 0.25
```

`is_suspicious = score >= 0.5`

**ThreatEvent `suspicion_score`:** mean of per-frame scores (`average_suspicion` from accumulated verdict).

**Meaning:** How **threat-like** the signal is overall (heuristic, not learned).

## 16. Known Limitations

1. All core detection tests use **synthetic or file-replay** audio — not over-air.
2. **No ML classifier** — rule-based modulation + heuristics only.
3. **OOK ~70%** reliable on synthetic (seeded in CI) — documented in KNOWN_ISSUES.md.
4. **STFT module** (`stft.py`) is offline-only — live path uses per-chunk FFT without overlap.
5. **ThreatEvent does not contain secret text** — by design.
6. **`pytest ai/tests/` alone from repo root** fails import — use `cd ai` or `pytest tests/ ai/tests/`.
7. **Encoded payload WAV** may show `pattern: tone` while `detected: true` — check `carrier_freqs`.
